# A frozen value editor transfers to arithmetic with one collateral error

The exact [recipient-only editor](reusable-symbol-value-edit.md) now transfers from a MOV immediate at byte 1 to an ADD imm8 operand at byte 3. All **16/16 intended destination words** and all **16/16 CF/ZF/SF/OF flag vectors** match independent arithmetic. Complete register states match in **15/16** rows: one edit also clears an unrelated register bit. This is a useful extension of the measured value interface, with a concrete limit on its selectivity.

The [prospective protocol](arithmetic-symbol-value-edit-protocol.md) froze the cases, controls and predictions before any native outputs. Terminal certification remains unassessed.

Reconstructing the carrier from the actual soft weights closes within `1.19209e-7`. The model's routing, rather than a new host offset argument to the editor, supplies this address change.

## Arithmetic changes include full carry chains

The 16 fixed cases cross four destination/before-state contexts with signed immediates `21`, `53`, `−107` and `−75`. Reflecting coordinate 5 changes the requested addend by `+32` or `−32`, while leaving its sign bit unchanged. The contexts cover ordinary arithmetic, carry, zero/wrap and signed overflow. Every register bank is populated; exact evaluation-counterfactual input envelopes are excluded from the native parent panel by distinct unchanged program tails.

For example, R0 begins at 96. The original addend `−107` produces `−11`; the reflected addend `−75` produces `21`. The unchanged arithmetic consumer changes **59 result bits**, after only one carrier coordinate was edited. Native COPY then carries 21 into R3, and native ADD-one produces 22. The reciprocal direction works as well. This is evidence of an operand used by arithmetic, beyond transporting one output bit.

The main arm's 256 mathematically changing target bits all have positive intended margins, with minimum `0.3107493`. Their signed logit movements range from `9.1541233` to `37.7321548`. The observed total of 256 register-bit changes alone would conceal the exception below; coordinate identity and full-state comparison matter.

## The exceptions distinguish editing from native competence

In `arithmetic-3-15`, the before-value is R7=`0x7fffffffffffffd0`. The original native ADD-21 misses R7 bit 26, producing `0x7ffffffffbffffe5` instead of `0x7fffffffffffffe5`. The carrier edit correctly produces the requested ADD-53 destination `0x8000000000000005` and overflow flags, but also clears **R5 bit 13**: `0xaa55aa55aa55aa55` becomes `0xaa55aa55aa558a55`. The evaluation-only raw-input counterfactual has the correct complete register state. This is an edit-specific collateral failure in a row that also contains a distinct original native error.

In `arithmetic-3-35`, the carrier edit correctly produces `0x7fffffffffffffe5` with every other register preserved. The raw-input counterfactual instead misses R7 bit 26. Consequently, 14/16 complete-register agreement with that comparator does **not** mean two failed edits. One disagreement is collateral in the edit; the other is a native counterfactual error while the edit is arithmetically correct. The independent equations never repair either branch.

The bit-4 specificity control has its own error in `arithmetic-2-15`, missing R5 bit 14. Its requested addend delta is `−16` in all rows, rather than a null perturbation. Upper-coordinate reflection is also a measured preservation contrast, not a certified null: it preserves hard registers/flags while changing raw register logits by up to `1.79000` and a disabled store-value bit. No unfavorable row is removed.

The first main edited output is not numerically identical to its raw-input counterfactual. Maximum register-logit difference is `1.61009`, and maximum flag-logit difference is `2.16436`. Relative to the original native parent, destination, source, width, length, store-enable and syscall logits remain exactly unchanged; registers, flags, immediate and inactive store outputs move. The store gate remains disabled. Correct arithmetic flags here require some large flag-logit changes, so preservation of the original flags would be the wrong criterion.

## The unrelated bit crosses the learned output projection

Astra's [saved-state analysis](../outputs/arithmetic-symbol-edit-advisor-nn/readout-projection.json) reconstructs the R5 bit-13 logit from the actual final hidden vector and frozen `reg_out` weights. The supplied copy prior remains `+4`. The native learned contribution is `+5.13555384`, yielding logit `+9.13555336`; after the operand reflection, the learned contribution becomes `−4.18443775`, yielding `−0.18443775`. Its hidden-vector/weight decomposition accounts for the `−9.31999194` logit change within `8.3e-7`. The [reproducible analysis source](../outputs/arithmetic-symbol-edit-advisor-nn/readout_projection.py) verifies the public stored cuts, actual output heads and frozen weights without constructing or forwarding the model.

The raw-input counterfactual's saved output margin is `+0.14119220`, so the carrier edit lies `0.32562995` below it and crosses the preservation boundary. This architecture adds a shared learned output to a copy prior; it has no hard destination-write mux guaranteeing that other registers stay fixed. The arithmetic operand effect can therefore coexist with an unintended output bit change. This is numerical localization of the failure, not proof of an individual neuron's semantic role or the upstream cause of the edit/counterfactual difference. The counterfactual hidden vector was not captured and is not regenerated for this analysis.

The resulting interface contract needs a preservation footprint alongside its reader, context and lifetime. An Act that changes only one carrier coordinate can affect multiple native outputs. A stronger editing claim must account for that downstream footprint, rather than infer selectivity from the Act's narrow write list.

## Later native use preserves both intended values and mistakes

Each completed branch receives COPY followed by ADD-one, using its own predicted register bank, flags and instruction length. All 224 successor rows across seven trajectories reach the planned byte offsets 4 and 7. Their COPY/ADD register and flag computations are correct for those actual inputs. The main trajectory has 16 rows per later call, including the row with collateral; no oracle state repairs that row.

The 15 correct first-call complete states remain correct through both uses. The R5 collateral in the remaining row survives. Main and evaluation-counterfactual later outputs match exactly across eleven heads in 14/16 rows at each step, because the different first-call errors remain present. These later calls establish native use and lifetime through the supplied ABI, rather than 32 independent replications of first-call semantics.
