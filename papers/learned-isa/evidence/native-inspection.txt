# What resembles the native binary inside the ISA models?

The familiar structure is an x86 instruction-family decoder connected to a supplied architectural state machine. The ADD sequence is visible in the committed program state. The learned ADD carrier remains identical while the counter changes. The SSM scans are causally involved in family recognition, with recipient-dependent behavior under replacement; arithmetic and program-state carry are supplied by the shared runtime.

Frozen three-seed captures: `job-3f80146577e9`. Independent per-step native hardware acquisition is unavailable; no hardware state-parity claim is made.

| Native counter bytes | Role | Who provides it here? |
|---|---|---|
| `31 ff` | XOR EDI,EDI: initialize RDI | Learned family selection; supplied XOR effect |
| `48 83 c7 01`, thirteen copies | ADD RDI,1: count | Learned family selection; supplied ADD and flags |
| `b8 3c 00 00 00` | MOV EAX,60: exit syscall number | Learned MOV family; supplied immediate/register decoding |
| `0f 05` | SYSCALL | Learned family; supplied Linux service |

This binary has an unrolled ADD chain. It contains no loop backedge, so a repeated activation is not evidence of a learned loop.

Each of thirteen ADDs has the same bytes/features and identical captured neural activations (or structural route/address), while RDI advances from 0 to 13. A common-parent Saturn Act sets RDI to 0, 1, 41 or 2^64−1 before the ADD. The learned carriers remain identical; the consumer produces 1, 2, 42 or 0. Parent replay matches the recorded RDI result and full decoder activations exactly. This replay check does not certify a whole-process snapshot. This localizes the counter value and arithmetic effect to the supplied architectural state/consumer, not a recurrent learned register.

Changing the emitted family from ADD to SUB stops execution before a register write. The learned route is therefore consumed; the runtime does not silently repair a wrong family.

## Paired SSM output interventions

Saturn captures the actual selective-scan output before the native mixer consumes it. Each arm forks the same typed parent; only that output changes. Numeric features, convolution/skip/diagonal paths, parameters and native consumer remain fixed. Wrong-source uses the other instruction's scan output; random is norm matched. These are paired branches, not independent specimens.

The raw report retains every label, confidence, logit change, parent identity and Act receipt, including counter-trends. Zeroing a path that still leaves a correct answer does not establish that the path is generally unnecessary; parallel supplied features and learned skip/diagonal paths remain available. A donor-shaped tensor that changes the family does not by itself establish a portable instruction program.

Mamba/Hydra state resets for each instruction. The captured recurrent states process the instruction bytes, while the shared runtime carries architectural registers/memory across instructions. No learned register file, learned ALU, full compiler recovery, arbitrary-x86 equivalence or trained cross-instruction SSM state is claimed.

Native comparison, when available: identical ELF hashes; compare PC, initialized RDI/RAX, stack-relative RSP, stack bytes after store and CF/ZF/SF/OF. Initial ABI-undefined registers, absolute ASLR stack addresses, untracked flags and kernel-clobbered unused registers are outside this comparison. The initial native GDB instrument was unavailable on Beast; its status remains in the original capture. No independent per-step hardware comparison is available in this report.
